# E3.3 часть 3 — Интеграция отчёта

> **For agentic workers:** каждая задача ниже — отдельный бид. Реализация по TDD.
> **Тяжёлые проверки не запускать** — `cargo mutants`, `cargo test --workspace` и
> сетевые тесты гоняет супервайзер в конце эпика.

**Goal:** довести биржевую цену до числа в отчёте, заменить смешанный признак
полноты двумя величинами с разными знаменателями и выдать ликвидационную оценку
так, чтобы её нельзя было принять за цену выхода.

**Architecture:** сценарий отчёта собирает кандидатов из рыночного хранилища тем
же путём, каким уже собирает курсы ЦБ. Ядро применяет к ним версионированную
политику части 2 и возвращает выбранные цены вместе с непокрытыми позициями.
Полнота считается двумя раздельными величинами; `is_complete()` исчезает.

**Tech Stack:** Rust 2024, `rustc 1.98.0`.

## Global Constraints

- Все команды через `nix develop --command <…>`.
- Журнал фактов и `SCHEMA_VERSION` событий не трогаются.
- `iaam-core` не зависит ни от одного крейта проекта.
- Существующие тесты не переписываются: механическая адаптация разрешена,
  изменение утверждения — нет. Приёмочные тесты §15.4 обязаны остаться зелёными
  без ослабления.
- Дизайн: `.internal/specs/2026-08-26-e3-3-valuation-policy-design.md`, разделы
  2, 5 и 6.

### Task 1: ценовой вход из рыночного хранилища

Сегодня `PriceBoard` наполняется только событиями `Valuation`, и биржевые цены
E3.2 до отчёта не доходят вовсе. Курсы ЦБ уже ходят мимо журнала —
`official_fx_table` (`crates/iaam-app/src/scenarios/reports.rs:123`). Цена
получает ту же форму.

**Files:**
- Modify: `crates/iaam-app/src/scenarios/reports.rs`
- Test: `crates/iaam-app/tests/`

**Interfaces:**
- Consumes: `candidate_from_market_observation` из части 2,
  выборку наблюдений рыночного хранилища.
- Produces: функция сборки кандидатов по контуру и дате, симметричная
  `official_fx_table`: читает наблюдения по окну `(инструмент, дата,
  knowledge_as_of)` и отдаёт кандидатов отчёту отдельным входом.

**Acceptance Criteria:**
- Кандидаты собираются только по инструментам, реально присутствующим в
  позициях контура: лишних запросов к хранилищу нет.
- Окно чтения ограничено `knowledge_as_of` запроса — чтение на меньшую
  координату возвращает прежний набор.
- Кандидаты из журнальных событий `Valuation` продолжают поступать; биржевой
  вход их не вытесняет и не перезаписывает.
- Отсутствие наблюдений по инструменту — не ошибка сценария: позиция просто
  остаётся без кандидата, решение принимает политика.

- [ ] **Шаг 1: падающий тест** — сценарий отчёта по счёту с позицией, для которой
  в рыночном хранилище есть наблюдение, возвращает стоимость, посчитанную по
  биржевой цене, а не «нет данных». Помощники брать из существующих тестов
  `crates/iaam-app/tests/`.
- [ ] **Шаг 2:** `nix develop --command cargo test -p iaam-app` — FAIL.
- [ ] **Шаг 3:** реализация по образцу `official_fx_table`.
- [ ] **Шаг 4:** `nix develop --command cargo test -p iaam-app` — PASS.
- [ ] **Шаг 5:** коммит `feat(app): биржевая цена доходит до отчёта`.

### Task 2: политика применяется, `is_complete()` уходит

**Files:**
- Modify: `crates/iaam-core/src/returns/mod.rs` — сборка позиций (около строки
  365) и `data_quality` (около строки 500)
- Modify: `crates/iaam-core/src/valuation.rs` — удаление `is_complete`
- Test: там же

**Interfaces:**
- Consumes: `ValuationPolicyV1`, `SelectedPrice`, `UncoveredReason` из части 2.
- Produces: две величины полноты в `ReturnsReport`.

**Acceptance Criteria:**
- `PriceQuality::is_complete()` удалён; его единственный продакшн-потребитель
  переписан.
- **Покрытие меряется позициями, а не долей стоимости**: «оценено N из M» плюс
  список непокрытых с причинами. Доля стоимости для покрытия не вычисляется
  вовсе — стоимость непокрытой позиции неизвестна, поэтому знаменателя нет.
  Тест доказывает, что при непустом списке непокрытых процент стоимости
  **не выдаётся**.
- **Исполнимость меряется долей стоимости оценённых позиций**, и знаменатель
  назван явно. Деньги, требования и обязательства в знаменатель не входят.
- Доли даются по трём значениям: `Executable`, `IndicativePreviousClose`,
  `Unknown`; сумма долей равна единице с точностью денежного режима.
- Позиция, оценённая через `LegacyDerived`, попадает в долю `Unknown` и
  отдельно видна в отчёте как непересчитываемая наследственным правилом.
- Обе величины присутствуют в отчёте одновременно: тест падает, если
  исполнимость выдана без покрытия рядом.

- [ ] **Шаг 1: падающие тесты** на обе величины и на отсутствие процента
  покрытия при непустом списке непокрытых.
- [ ] **Шаг 2:** `nix develop --command cargo test -p iaam-core` — FAIL.
- [ ] **Шаг 3:** реализация.
- [ ] **Шаг 4:** `nix develop --command cargo test -p iaam-core` — PASS.
- [ ] **Шаг 5:** коммит `feat(core): две величины полноты вместо смешанного признака`.

### Task 3: `liquidation_value` с машинно видимыми квалификаторами

**Files:**
- Modify: `crates/iaam-core/src/returns/mod.rs`
- Test: там же

**Acceptance Criteria:**
- Величина не называется голым `liquidation_value`: структура несёт долю по
  исполнимости, издержки выхода и налог как **`Unknown`**, а не как ноль.
- Подставить ноль вместо неизвестных издержек невозможно по типу — тест
  доказывает, что `Unknown` не сравнивается с нулём и не складывается с ним.
- Отчёт называет величину «до издержек выхода и до налога», как XIRR уже
  называется «до налога» (`crates/iaam-core/src/returns/mod.rs:3`).
- Тест на данных, где все цены `IndicativePreviousClose`: доля исполнимости
  показывает ноль по `Executable`, и это не считается ошибкой расчёта.

- [ ] Шаги 1-5 по той же схеме; коммит `feat(core): ликвидационная оценка с квалификаторами`.
