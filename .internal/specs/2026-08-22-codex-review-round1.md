# Ревью спецификации, раунд 1 (codex)

Оговорка ревьюера: налоговые тезисы требуют финальной проверки по редакции НК РФ,
действующей для конкретного налогового периода.

## Критические

1. **§5.1/5.3/5.6 — ликвидационная оценка вклада.** «Вклад до выплаты стоит ровно тело»
   неверно как общее правило: условия досрочного расторжения могут сохранять часть
   процентов, капитализированные проценты уже в теле. §5.3 противоречиво ссылается
   и на ликвидационную оценку, и на договорный график начисления. Предложено до пяти
   оценочных баз. → **раунд 2**

2. **§4.1/5.6 — начисление процентов не является фактом `income`.** Расчётное начисление
   не внешняя операция, отменяется при досрочном расторжении. Факт — договор и его
   версии; начисление строится проекцией. → **принято, механика сверки в раунде 2**

3. **§4.5/6.2 — FIFO не глобальная очередь.** Нужна область применения: налогоплательщик,
   налоговый агент, налоговая база, инструмент, счёт, режим ИИС, год. Разделить
   экономические и налоговые лоты. → принято

4. **§6.2–6.4 — налоговых баз несколько.** Дивиденды, обращающиеся/необращающиеся бумаги,
   ПФИ, проценты по вкладам относятся к разным базам с разными правилами сальдирования.
   Дивиденды нельзя уменьшить убытком от продажи акций. → принято

5. **§6.2/6.4 — «необлагаемый минимум» по вкладам сформулирован устаревше.** Это не
   расходуемый по банкам лимит: база считается по совокупности процентов за год,
   необлагаемая сумма — по формуле с ключевой ставкой. Налог рассчитывает ФНС. → принято

6. **§7.2–7.4 — сверка из того же отчёта не независима.** Общая ошибка парсера исказит
   и операции, и контрольные остатки. Не ловятся: компенсирующие пропуски, перепутанные
   даты внутри интервала, парные buy+sell, неверное разнесение комиссии и НКД, неверная
   цена при верных количестве и сумме, swap одинаковых количеств, неверная валюта с
   компенсирующим курсом. Предложен статус `provisional` до независимого подтверждения.
   → **раунд 2: чем повышается статус без участия человека**

7. **§4.1 — нет `security_transfer`.** Перевод бумаг между брокерами станет фиктивной
   продажей и потеряет ЛДВ и затраты, при этом деньги сойдутся. → принято

8. **§4.1/4.5 — нет шортов, маржи, РЕПО.** Отрицательное количество разрушит инварианты
   лотов и FIFO. → **раунд 2: подтвердить исключение из периметра**

9. **§5.4 — тождество разложения не определено.** Не задано, что такое «итог»; частичная
   продажа без basis released, амортизация как мнимый доход, валютный результат с
   перекрёстным членом, налог другого периода. → **раунд 2: полное тождество**

10. **§12 — этап 1 обещает больше, чем даёт.** Ранний API закрепит семантику до
    проектирования налогов и TWR. → **раунд 2: минимальное необратимое ядро**

## Высокая серьёзность

11. **§4.1 — одной `occurredAt` недостаточно.** Нужны trade/settlement/cash posting/
    entitlement/payment даты и налоговый период. → принято
12. **§4.1/6 — налог через несколько лет не выражается.** Нужны `tax_assessed`,
    `tax_withheld`, `tax_paid`, `tax_refunded`, `tax_credit_applied` с налоговым годом,
    базой, агентом. → принято
13. **§4.1 — `corporate_action` как универсальный тип.** Не покрыты merger, spin-off,
    обмен ISIN, делистинг, банкротство, rights issue, дробные остатки. → принято
14. **§5.6 — «амортизация уменьшает лот» неверно.** Уменьшается непогашенный номинал,
    количество бумаг остаётся. Хранить quantity, nominal per unit, remaining principal
    раздельно. → принято
15. **§5.1/5.6 — ликвидность НКД не гарантирована.** Нужен доступный bid, режим торгов,
    издержки; при отсутствии исполнимой цены — неполное значение. → принято
16. **§5.6 — флоатеры.** Нужны fixing date, reference index, observation lag, spread,
    floor/cap, day-count, fallback. → принято
17. **§5.6 — оферта это право, а не автоматическое действие.** Факт — поданная заявка
    и совершённый выкуп. → принято
18. **§4.1/5.6 — замещающие облигации.** Разделить denomination/settlement/quote/
    reporting currency, добавить lineage инструмента. → принято
19. **§6.2 — валютная переоценка смешивает управленческий и налоговый учёт.** Разделить
    economic FX attribution и taxable FX events. → принято
20. **§6.2 — ИИС не один флаг.** Нужен версионированный `account_tax_regime`. → принято
21. **§7.6 — `opening_position` недостаточна.** Нужны provenance и confidence; налоговый
    отчёт должен уметь вернуть диапазон или `not computable`. → принято
22. **§7.4/7.6 — названный остаток подтверждает только снимок.** Сверка должна быть
    многомерной и интервальной, статус — по измерению и периоду. → принято

## Средняя серьёзность

23. **§1/5.5 — критика YTM неточна.** YTM корректна как IRR обещанных потоков к текущей
    цене; допущение о реинвестировании нужно лишь для интерпретации её как реализованной
    сложной доходности. «Простая доходность без капитализации» не является стандартной
    метрикой. → **раунд 2: дать определение**
24. **§5.2 — XIRR не определён для мультивалютности.** Зафиксировать валюту отчёта,
    источник курса, версию контура; показывать local-currency return и FX contribution.
    → принято
25. **§5.3 — TWR требует оценки до/после внешнего потока.** Задать timing convention;
    при отсутствии цены — Modified Dietz с явной маркировкой. → принято
26. **§5.4 — «до копейки» недостижимо.** Rounding residual неизбежен. → раунд 2 (в
    составе тождества)
27. **§4.2 — семантика `correction` недостаточна.** Конкурирующие коррекции дают
    зависимость от порядка импорта. Выбрать reversal+replacement либо version chain.
    → принято
28. **§4.1/7.5 — естественный ключ дедупликации слаб.** Нужны source operation ID,
    fingerprint нормализованной записи, document hash + row locator, вероятностный score.
    → принято
29. **§3.2 — запрет зависимости `tax/` от рыночных данных нереалистичен.** Налоговая
    функция принимает подготовленный immutable tax context. → принято
30. **§3.4 — минимальных единиц недостаточно.** Разделить posted money и calculation
    amounts в Decimal. → принято
31. **§8 — last-known price конфликтует с оценкой неликвида.** Нужна valuation policy
    по классам активов с quality flag. → принято
32. **§10 — JSONL не является полным бэкапом.** Нужен версионированный archival bundle
    с инструментами, счетами, правилами, договорами, provenance, checksums. → принято
33. **§11 — золотые сценарии не покрывают опасное.** Добавить: перенос бумаг,
    доудержанный налог, возврат налога, дивиденд в валюте, замещающая облигация, оферта
    без предъявления, сплит с дробным остатком, делистинг, частичная история без basis,
    отрицательный cash, одинаковые сделки, компенсирующая ошибка парсера. → принято

## Главный вывод ревьюера

Этап 1 нельзя проектировать вокруг long-only лотов, одной даты события и XIRR. До начала
реализации нужно зафиксировать временную модель, различие экономических и налоговых лотов,
типизированные движения денег/бумаг/обязательств, многовалютность и формальное тождество
P&L — иначе этапы 4–5 потребуют миграции журнала фактов, заявленного неизменяемым
фундаментом.
