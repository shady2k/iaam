## Часть C — предметная корректность

1. **Округление.** Продакшн (`Decimal::round_dp_with_strategy` с `MidpointNearestEven`) и эталон (целочисленный `round_half_to_even`) совпадают на всех пяти случаях фикстуры. Проверено вручную для «2 шт за 5 копеек» (обе дают 2) и «3 шт за 1000» (обе дают 333).

2. **Свойство сохранения стоимости** выполняется точно: частично разделён может быть не более одного лота, для него `kept = original - taken`. Число лотов на доказательство не влияет.

3. **`legs_balance` — ошибка проектирования.** Освобождение от проверки всего, что имеет бумажную ногу или пересекает границу контура, пропускало покупку с неверным знаком денег, продажу без денежного прихода, двойную комиссию, НКД вне расчёта — и одновременно **отвергало корректную комиссию с одной ногой**. Заменено на `validate_structure` с проверкой формы по типу события.

4. **`CashTransfer` без второго счёта — ошибка проектирования.** Классификатор физически не мог знать второй счёт, поэтому перевод с внешнего вклада на внутренний брокерский счёт получал бы `Internal`. Пометка «ограничение этапа 1» неприемлема: событие необратимо, а §16.1 существует ровно для предотвращения таких записей. Тест «тот же перевод для узкого контура» вдобавок подменял `CashTransfer` на `CashIn` и перевод не тестировал. Исправлено: `CashTransfer { transfer_id, from, to, amount }`, классификация по паре принадлежностей, `FlowClass` разделён на `ExternalIn` и `ExternalOut`.

5. **Рантайм-валюта `Money`** признана разумным компромиссом. Усилено: поле `PostedMinor` сделано приватным — публичное `pub i64` делало обход тривиальным.
