# IAAM — учёт инвестиций

## Что система умеет сейчас

IAAM принимает факты тремя независимыми путями:

- брокерский отчёт — через `POST /v1/ingest/csv` и загрузку документа
  `POST /v1/documents`; строки разбираются отдельно и получают собственный
  вердикт;
- операции из API — через `POST /v1/ingest/operations`. Внутри приложения
  есть отдельные клиенты и разбор ответов API брокера; общий код разбора с
  отчётным каналом не используется, чтобы ошибка одного канала не
  маскировала ошибку другого.

Корпоративные действия приходят третьим входом — `POST
/v1/ingest/journal-events`: амортизация, погашение, замещение и исполнение
оферты записываются типизированными фактами, а не подгоняются под покупку
и продажу.

Журнал остаётся источником истины, а сверка строится заново по интервалу и
измерению: `cash`, `positions`, `income` и `tax_basis`. Для измерения
система различает `provisional`, `accepted_internal`,
`accepted_independent` и `discrepant`. Независимое подтверждение возможно,
например, когда API брокера подтверждает разобранный отчёт; два отчёта,
разобранные тем же парсером, независимым каналом не становятся.

Инструменты живут в общем справочнике: `GET|POST /v1/instruments` и
`POST /v1/instruments/resolve`. Внешний код разрешается **на дату
документа**, а не на сегодня, потому что ISIN выпуска меняется при
замещении, и код, разрешённый «сейчас», указал бы на другую бумагу.

Рыночные данные система получает сама. `POST /v1/market/sync` тянет одну
серию с MOEX ISS или ЦБ РФ и пишет наблюдения append-only, а `GET
/v1/market/prices`, `/v1/market/fx` и `/v1/market/key-rate` отдают их
обратно на выбранную координату знания. Запуск ручной: периодического
планировщика нет.

`POST /v1/brokers/{broker}/sync` синхронизирует один счёт за переданный
интервал и возвращает построчный итог; если ключ или доступ брокера не
настроены, маршрут отвечает `503`. Правила классификации
(`GET|POST|DELETE /v1/classification-rules`) хранят историю версий, и
добавление или удаление правила запускает пересчёт этой истории.

Отчёт `GET /v1/reports/returns` возвращает доходность **до налога**,
стоимость контура, применённые правила и блок `data_quality`. В нём есть
доли стоимости по четырём статусам и материальные проблемы. Цену позиции
выбирает правило оценки с собственной версией, и отчёт называет, что
именно применено: наблюдение дня, перенос с прошлых торгов или величина,
выведенная из старой оценки. Свести их в одно число значило бы стереть
разницу между «биржа торговала» и «мы подставили вчерашнее». Периметр §11
сохраняет наблюдаемый денежный эффект, но не выдумывает экономику для
маржи, РЕПО, шортов и других неподдерживаемых случаев; такой случай может
сделать отчёт за затронутый счёт невычислимым, не отменяя остальные счета.

## Чего система пока не умеет

Система не считает налоги, TWR, NAV-ряд и доходность за произвольный
подинтервал, не поддерживает шорты, маржу и производные как экономику
портфеля, не восстанавливает потерянный ключ шифрования из одной базы
и не имеет веб-интерфейса. Периодический планировщик синхронизации,
депозитарный отчёт и справка налогового агента отложены.

По облигациям отчёт отдаёт накопленный купонный доход, реализуемую при
выходе сумму и дату ближайшей выплаты, а возврат номинала знает, окончателен
ли он. НКД считается по графику выплат версионированным правилом и сверяется
с наблюдением биржи; расхождение больше копейки попадает в качество данных,
а не разрешается молча. Ставки флоатера, формулы купона, ряда RUONIA и
опубликованных фиксингов пока нет.

Биржевая цена входит в стоимость контура: покрытие и `terminal_value`
считаются из одной оценки позиции, поэтому «покрыта» и «стоимость известна»
больше не расходятся. Позицию, стоимость которой пересчитать нельзя, отчёт
называет непокрытой с типизированной причиной, а не выдаёт за оценённую.

Основание котировки сверяется с признаком, по которому оно выведено.
Несогласованная или недоказанная пара гасит **позицию**, а не отчёт: остальные
счета считаются, а затронутая позиция уходит в непокрытые. Противоречие
признаку и отсутствие доказательства — разные причины, потому что ведут к
разным действиям: первое означает дефект источника, второе — исторически
неполную запись. Витрина `GET /v1/market/prices` называет это прямо:
`quotation_basis` — эффективное основание, `recorded_quotation_basis` —
основание ровно в записи источника, `quotation_basis_status` — `proven`,
`contradicts` или `not_proven`.

Порядок дальнейших работ — в `.internal/specs`.

См. `docs/deployment.md`. Описание API для внешнего агента —

## Разработка

Все команды выполняются внутри `nix develop`.

- Тулчейн: `rustc 1.98.0 (88d9e12ae 2026-08-18)` (`cargo 1.98.0 (797e8a9bc 2026-08-05)`)
- Редакция: 2024

```bash
nix develop            # войти в окружение
cargo test --workspace
```

С `direnv` (файл `.envrc` в корне) окружение подхватывается при входе в
каталог, и префикс `nix develop -c` не нужен.

## Заслоны качества

Каждый заслон проверен падением на намеренно внесённом нарушении.
Настроенный, но непроверенный заслон хуже отсутствующего — он создаёт
ложную уверенность. Три из них при такой проверке оказались fail-open
и были переписаны.

| Заслон | Команда | Что ловит |
|---|---|---|
| Формат | `cargo fmt --all -- --check` | расхождение стиля |
| Линты | `cargo clippy --workspace --all-targets --all-features -- -D warnings` | деградацию качества |
| Запрет `unsafe` | компилятор, через `[workspace.lints.rust]` | `unsafe` в крейтах первой стороны |
| Архитектура | `./scripts/check-architecture.sh` | направление зависимостей, `f64` и `async` в ядре, крейту без `[lints] workspace = true` |
| Diff-lint | `./scripts/check-diff-lint.sh <база>` | новые `allow`/`expect`/`ignore`/`todo!` и правку файлов политики |
| Фикстуры | `./scripts/check-fixtures.sh` | правку замороженного эталона и мёртвые фикстуры |
| Зависимости | `cargo deny check` | уязвимости, лицензии, неизвестные источники |
| Тесты | `cargo nextest run --workspace` | регрессии |
| Покрытие по диффу | `diff-cover lcov.info --fail-under=90` | непокрытый новый код |
| Мутации | `./scripts/check-mutants.sh` | тесты, проходящие впустую (порог по каждому модулю) |

**Заслон не чинится ослаблением.** Если он мешает — либо код неверен, либо
заслон требует осознанного исключения, вносимого отдельным коммитом
с обоснованием.

### Изменение файлов политики

`check-diff-lint.sh` помечает правки в `scripts/`, `.github/workflows/`,
`deny.toml`, `clippy.toml`, `.cargo/mutants.toml`, `Cargo.toml`,
`tests/fixtures/`, `flake.nix`, `flake.lock` и `rustfmt.toml`. Такие
изменения проходят CI только с переменной `POLICY_CHANGE_APPROVED=1`,
которую выставляет владелец репозитория, а не агент.
