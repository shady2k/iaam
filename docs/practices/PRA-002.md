# PRA-002 — A box worker ends its turn while a command it started is still running

Status: active
Since: 2026-11-14
Evidence: box sessions of 2026-11-12..14 (prime agent, gpt-6.1-sol) on iaam-xzz5.4 and iaam-xzz5.5.x: turns ended with cargo builds and tests still running and changes uncommitted; `box wait --strict` exited 6.

## Class

A worker in a box answers before its work is done: a command it started is
still running, its changes are uncommitted, and the turn's answer is read as
the result.

## Mechanism

The agent treats a started command as progress and answers; the harness lets a
turn end with work still running.

## Practice

Every brief to a box worker says: run commands in the foreground, never put a
cargo command in the background, do not end the turn while a command runs, and
commit before ending the turn.

The coordinator waits with `box wait <id> <session> --strict`. On exit 6 it
sends "wait for it, then finish" instead of reading the turn's answer as the
result.

## How we will know

No exit 6 in the next period's box waits.
